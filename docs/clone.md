# 零拷贝克隆与写时复制设计

warehouse/tables.py 在 objects.py(内容寻址不可变对象)与 catalog.py(比较更新目录)之上实现分块表、克隆、读句柄与容量账。本文是设计约定。

## 对象布局

所有对象不可变,按正文 SHA256 寻址:

- 字段目录 `{'format':1,'fields':[{'id','name'}...],'defaults':{字段ID:缺省值}}`。字段 ID 稳定,改名只换 `name`;`defaults` 里出现的键才有缺省,`null` 可以作为显式缺省值。
- 数据块 `{'format':1,'rows':[行,...]}`,块内行按 `row_id` 升序且唯一。
- 清单 `{'format':2,'schema':<目录摘要>,'blocks':[{'digest','first','last','rows'}...],'rows':总行数}`。块区间有序、不相交、非空。**清单不含表身份**,因此可以被多张逻辑表共享。
- 目录条目 `{'table':<表身份>,'head':<清单摘要>[,'origin':{'table','head'}]}`,表身份由目录名派生(`tbl-` 前缀哈希),克隆与源表身份必然不同;`origin` 记录克隆来源。

## 克隆

`clone(src,dst)` 只向目录写入一条新条目:新表身份 + 源表当前清单头。**不写入任何数据对象**(演示中 `puts==0`、`put_bytes==0`),这是存储层的零拷贝,不是复制仓库后改名。重试安全:目标已存在且身份与来源相符时直接返回既有条目,绝不改动已提交的克隆。

## 写时复制

一次写入(upsert/delete)的对象阶段:

1. 按 `row_id` 对块索引二分定位,**只装载受影响的块**;未触及的块连读都不读,直接以摘要复用进新清单。
2. 受影响块应用 upsert(整行替换或插入)与 delete(按 `row_id` 移除,缺席为无操作),重新排序后按块行数上限顺序切块,写出新块。
3. 写出新清单,以目录 CAS 切换 `head` 为唯一提交点。

行身份的保持:行只随 `row_id` 在块间重新分布,拆块不产生或丢失行;删除只移除目标行,其余行的 `row_id` 与内容不变;空块直接丢弃,不做合并(避免无关重写)。字段缺省只在读取时物化到该快照物理缺席的字段上,物理行永不改写;显式 `null` 不被缺省覆盖。

任一侧写入都只产生新对象,共享块的内容永远不会被原地修改(对象层根本不存在原地写接口)。

## 中断与重试

- 对象写入幂等:内容寻址,重复 `put` 去重,不新增字节。
- 目录 CAS 是唯一提交点;对象阶段完成后、提交前崩溃,目录仍是旧版本,重试重新执行同一对象阶段会得到同一个新清单头(内容确定),再提交即可。`prepare_write`/`commit_write` 两段式接口支持显式重试,`write` 内置冲突重试循环。
- 目录锁是 flock 文件锁,进程崩溃由内核自动释放,残留锁文件不阻塞重试;引用切换走临时文件加原子替换,中途断电只会看到旧值或新值。

## 读句柄

`open(name)` 固定打开时刻的(表身份, 清单头),并登记一条有过期时间的 pin;保留期内 pin 是容量账的有效根,过期或 `close()` 后不再是根。源表与克隆的读句柄各自独立,互不影响版本。

## 容量账

- 逻辑量:每张表可达对象集合(清单+字段目录+全部块)的字节和,共享块在每个表各计一次。
- 物理量:全体有效根(各表目录头 + 保留期内的 pin)可达对象并集的字节和,共享只计一次;`shared_bytes = 逻辑合计 - 表并集字节`。
- `gc_report` 报告在盘对象中不被任何根可达的部分(中断孤儿、被取代的历史版本),只报告回收资格,不实际清除。逻辑删表(`drop`)只移除目录条目,对象一个不动;被克隆或句柄引用的块永远不会出现在可回收清单里。

## 验证

`python -m warehouse.demo` 用真实对象读写统计展示:克隆零写入、源表推进时哪些块复用哪些重写、中断重试去重命中、容量账四项口径,并断言源表推进与删除后旧克隆仍能完整查询。`tests/test_tables.py` 覆盖上述全部约定。
